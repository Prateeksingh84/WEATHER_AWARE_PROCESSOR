# Yellow.ai AI Automation Intern — Assignment 2

## Weather-Aware Order Delay Processor

This project implements the assignment as a real-time Node.js program. It reads the exact `orders.json` sample, starts one current-weather request for each city concurrently, applies the Rain/Snow/Extreme rule, generates a personalized customer message for delayed orders, logs invalid-city failures, and writes an updated JSON file.

## Architecture

```text
orders.json
    |
    v
Validate input
    |
    v
Create one weather job per order
    |
    v
Promise.allSettled  <-- concurrent requests
    |
    +-----------------------------+
    |                             |
  fulfilled                    rejected
    |                             |
    v                             v
weather.main                 structured error
    |                             |
    v                             v
Rain/Snow/Extreme?           errors.log
   /       \
 yes       no
  |         |
  v         v
Delayed   retain status
  |
  v
Weather-Aware Apology
  |
  v
orders.updated.json
```

## Quick start

```powershell
cd "C:\path\to\yellow-ai-assignment2"
Copy-Item .env.example .env
notepad .env
npm install
npm test
npm start
npm run verify:live
```

Set the real key only in `.env`:

```env
OPENWEATHER_API_KEY=YOUR_REAL_KEY
```

## Outputs

```text
output/orders.updated.json
output/errors.log
```

The exact live `Delayed` results depend on current weather at the moment of execution. The assignment asks for current weather, so the submission must use the JSON generated by the live run rather than fabricated static results. Run `npm run verify:live` after the live run to validate the generated artifacts.

## Official OpenWeather reference

The current-weather API supports `q={city name}` and requires an API key. Its JSON includes `weather.main` and `weather.description`, which are used here for the assignment's golden flow.

## Security

`.env` is gitignored and the API key is never hardcoded in source code.

## Real-time dashboard

The project includes a zero-dependency local dashboard. It reads the live `output/orders.updated.json` and `output/errors.log`, streams the processor console in real time, and provides a **Run Weather Check** button that launches the same live processor as `npm start`.

Start it with:

```powershell
npm run dashboard
```

Open:

```text
http://127.0.0.1:4173
```

The dashboard does not receive or expose the OpenWeatherMap API key in browser code. The server starts `src/weather-orders.js` with the local `.env` configuration already loaded by the processor.
