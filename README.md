## 🏗️ Architecture

```
orders.json
     |
     v
Validate input
     |
     v
Create one weather job per order
     |
     v
Promise.allSettled  <-- concurrent requests, all cities at once
     |
     +-------------------------------+
     |                               |
  fulfilled                       rejected
     |                               |
     v                               v
weather.main                   structured error
     |                               |
     v                               v
Rain / Snow / Extreme?          errors.log
      /         \
    yes          no
     |            |
     v            v
  Delayed     retain status
     |
     v
Weather-Aware Apology Message
     |
     v
output/orders.updated.json
```

## 🚀 Quick Start

### 1. Setup

```powershell
cd "C:\path\to\yellow-ai-assignment2"
Copy-Item .env.example .env
notepad .env
```

Set your real API key in `.env`:

```env
OPENWEATHER_API_KEY=YOUR_REAL_KEY
```

### 2. Install & Run

```powershell
# Install dependencies
npm install

# Run tests
npm test

# Run the live processor
npm start

# Validate generated artifacts
npm run verify:live
```

### 3. Launch Dashboard

```powershell
npm run dashboard
```

Then open:

```
http://127.0.0.1:4173
```

## 📦 Outputs

| File | Description |
|---|---|
| `output/orders.updated.json` | All orders with updated status and apology messages |
| `output/errors.log` | Structured log of invalid-city failures |

> The exact live `Delayed` results depend on current weather at the moment of execution. The assignment asks for **current weather**, so the submission must use the JSON generated by the live run rather than fabricated static results.

## 🌐 Real-Time Dashboard

The project includes a **zero-dependency local dashboard** that:

- Reads live `output/orders.updated.json` and `output/errors.log`
- Streams the processor console output in real time
- Provides a **Run Weather Check** button that launches the same live processor as `npm start`
- Does **not** expose the OpenWeatherMap API key in browser code

```powershell
npm run dashboard
# Open http://127.0.0.1:4173
```

## ⚙️ How It Works

<table>
  <tr>
    <td width="50%" valign="top">
      <h4>🔄 Concurrency</h4>
      <ul>
        <li>One live weather request created per order simultaneously</li>
        <li><code>Promise.allSettled</code> waits for all — no order blocks another</li>
        <li>Fulfilled requests flow into the delay rule engine</li>
        <li>Rejected requests are written to <code>errors.log</code></li>
      </ul>
    </td>
    <td width="50%" valign="top">
      <h4>🌧️ Delay Rule Engine</h4>
      <ul>
        <li>Reads <code>weather.main</code> from OpenWeatherMap response</li>
        <li>Conditions that trigger <code>Delayed</code>: Rain, Snow, Extreme</li>
        <li>Unaffected orders retain their original status</li>
        <li>Every delayed order gets a personalised apology message</li>
      </ul>
    </td>
  </tr>
  <tr>
    <td width="50%" valign="top">
      <h4>🛡️ Resilience</h4>
      <ul>
        <li>Input validated before any network calls</li>
        <li>Invalid city failures are isolated per order</li>
        <li>One bad city never halts the entire run</li>
        <li>Structured error logging for every failure</li>
      </ul>
    </td>
    <td width="50%" valign="top">
      <h4>🔒 Security</h4>
      <ul>
        <li><code>.env</code> is gitignored — API key never hardcoded</li>
        <li>Key loaded only server-side via <code>.env</code> config</li>
        <li>Dashboard never exposes the API key in browser code</li>
        <li>Official OpenWeatherMap <code>q={city}</code> API used</li>
      </ul>
    </td>
  </tr>
</table>

## 🌍 OpenWeatherMap API

The current-weather endpoint supports `q={city name}` and requires an API key.

```
GET https://api.openweathermap.org/data/2.5/weather?q={city}&appid={key}
```

The response fields used:

| Field | Purpose |
|---|---|
| `weather[0].main` | Primary condition — checked against Rain / Snow / Extreme |
| `weather[0].description` | Included in the apology message for context |
